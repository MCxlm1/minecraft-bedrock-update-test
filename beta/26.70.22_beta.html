Technical Updates

Items

  • Added new tag for sulfur cubes to make use of for physics determination and absorbing:
    • minecraft:sulfur_cube_archetype_cold

AI Goals

minecraft:behavior.move_to_land

  • Now only targets land the mob has a full path to, so mobs no longer swim against a wall trying to reach land on the other side
  • No longer gives up as soon as it starts when goal_radius is smaller than the 2 blocks the mob moves past the land
  • When search_count is above 0, sampled positions are now snapped to the ground, so mobs in deep water find nearby land much more reliably

API

  • Fixed the Wither entity becoming invalid before scripts could access it in world.afterEvents.entityDie callbacks
  • The BlockMapColorComponent can now be fetched on any block (MCPE-240722)
  • PrimitiveText and DebugText are no longer hidden by the "In Game Player Names" option being disabled.

Biome Components

minecraft:tags

  • Added the frozen tag to the Ice Caves biome

Blocks

  • Box arrays in minecraft:collision_box have been updated as follows from version 1.26.70 and onwards:
    • 'origin' and 'size' have been deprecated in favor of 'min' and 'max'.
    • 'min' and 'max' were removed from version 1.26.60. Their minimum version is now 1.26.70 and they no longer require the "UpcomingCreatorFeatures" experiment to use.
    • The maximum box count limit for min and max arrays is now 32.
    • The component will not accept empty values.

Dedicated Server

  • Added pack optimization support to Linux dedicated server.

Editor

  • Added support for keyboard usage to affect structures in Layout Editor

Entity Components

  • Added the following fields to the minecraft:teleport component
    • target_teleport_distance: The minimum and maximum distance the entity can teleport towards its target
      • Defaults to [16.0, 16.0]
    • target_teleport_offset: The maximum random offset, on each axis (x, y, z) and in either direction, added to the teleport direction
      • Defaults to [4.0, 8.0, 4.0]
      • on_teleport_sound: Level sound event played after a successful teleport
        • Falls back to the default teleport sound if none is bound; use "undefined" for a silent teleport
        • Defaults to teleport
    • can_teleport_into_liquid: If set to true, the entity can teleport into blocks that contain liquids, such as water
      • Defaults to false

minecraft:trail

  • Updated the minecraft:trail schema for format version 1.26.70
    • block_type defines the trail block to place
    • shape defines the horizontal placement pattern as corners, square, or circle
    • extent defines the maximum horizontal distance from the center at which blocks can be placed
    • offset defines the trail block placement positions relative to the entity
    • placement_filter defines the entity conditions required before processing placement positions
    • placement_checks accepts none, block, or standard to control validation at each placement position
    • placement_conditions defines block requirements at vertical y_offset values from each placement position
      • Entries combine with AND and block_types within an entry combine with OR
      • When omitted, placement_conditions defaults to [{ "y_offset": 0, "block_types": ["minecraft:air"] }]
    • place_only_on_block_position_change limits placement to ticks where the entity moves into a different block or lands, and defaults to false

minecraft:transformation

  • transformation_sound now respects entity-specific sound mappings in sounds.json

Entity Event Responses

  • Added the "place_feature" entity event response, allowing features to be placed at the entity's position
    • The "feature" field allows to specify the type of feature to place
    • The "target" field allows to specify which target entity's position to place the feature at
    • This feature is currently only for internal use and will be made public in the future

User Interface

  • Core engine query hooks, except useIsPaperDollSkinReadyQuery, are no longer exported from @mojang/bedrock-core-engine, so screens read engine data through React context hooks and tests provide it with mock providers instead of faking raw queries
  • Screen reader state and user options now live in the standalone @mojang/react-screen-reader and @mojang/react-user-options packages
  • Split screen context values in @mojang/react-device-information are now facets and include isPrimaryUser
  • TestWrapper, visual regression examples and playground <Examples> now accept splitScreen, screenReader and userOptions props for mocking that data
  • Added "Close Creator Screens" keybinding to force close custom DDUI screens.

Experimental Technical Updates

API

  • Added class BlockItemFrameComponent to beta for inspecting, setting, replacing, and clearing the item displayed by item frames, with an option to drop the item when clearing
  • Added getRotation and setRotation methods to BlockItemFrameComponent in beta for inspecting and setting item frame rotation in 45-degree increments, from None through Clockwise315
